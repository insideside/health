# Trainer — архитектура

Локальное приложение для семьи или небольшой компании: чек-лист на каждый день, календарь, журнал питания,
программа тренировок, мотивация. Сервер работает на домашнем компьютере (macOS, Linux или Windows), клиенты —
iPhone/iPad (PWA) и браузеры в локальной сети. Всё работает офлайн и синхронизируется
при подключении. Локальная ИИ (Ollama) запускается **только по явному запросу**.

## Решения

| Вопрос | Решение |
|---|---|
| Сервер | Python 3.12, FastAPI + uvicorn, зависимости через `uv` (как transkribator) |
| Хранилище | SQLite `data/trainer.db` |
| Фронт | vanilla JS без сборки, дизайн-система «Стенограмма» (`stenogramma.css`, `theme.js` из transkribator) |
| Офлайн | Service Worker (оболочка) + IndexedDB (данные) + очередь исходящих изменений |
| HTTPS | самоподписанный сертификат с SAN на все IP и `<имя>.local`, CA ставится на iOS один раз (подход vk-music) |
| ИИ | Ollama на `localhost:11434`, модель класса Qwen3 14B–32B, JSON по схеме |
| Нормы | формулы (детерминированно) + ИИ проверяет реалистичность целей и объясняет |
| Видимость | аккаунты раздельные; прогресс (выполнение дня, серии, достижения) виден партнёру, питание и вес — приватны |
| Устройства | iPhone/iPad, Mac/ПК в браузере |

```

┌─────────────────────────────┐      ┌───────────────────────────────────┐
```

## Модель данных

Каждая синхронизируемая запись: `id` (UUID, создаёт клиент), `user_id`, `updated_at`
(время клиента), `rev` (монотонный счётчик сервера), `deleted`.

| Таблица | Содержимое |
|---|---|
| `users` | логин, хэш пароля, имя, пол, дата рождения, рост, активность, `gym` (да/нет), дней в неделю, домашний инвентарь, тон мотивации |
| `goals` | исходный текст цели + разобранные поля (`fat_kg`, `muscle_upper_kg`, `muscle_lower_kg`, …), срок |
| `targets` | версии норм: ккал, Б/Ж/У, вода (стаканы), шаги, `valid_from`, источник, пояснение ИИ |
| `exercises` | общий каталог: название, техника по шагам, ошибки, мышцы, оборудование, уровень, варианты облегчения/усложнения |
| `programs` | мезоцикл: цели, место (зал/дом), дни недели, даты, прогрессия |
| `workouts` | дата → упражнения: `exercise_id`, подходы × повторы, вес, отдых, комментарий; факт по подходам |
| `checklist_items` | шаблон пользователя: `bool` (элемент зарядки), `counter` (вода), `number` (шаги), `workout` |
| `day_log` | `(user, date, item_id)` → значение |
| `food_entries` | дата, приём пищи, исходный текст, позиции `[{name, grams, kcal, p, f, c, source}]`, статус `raw/calculated` |
| `foods` | справочник на 100 г; стартовый набор + всё, что пользователь уже ел (источник `db/ai/manual`) |
| `body_log` | вес, замеры |
| `achievements` | выданные достижения |
| `coach_messages` | сообщения мотивации (шаблонные и от ИИ) |
| `ai_jobs` | тип, вход, статус, результат, ошибка |

## Синхронизация

1. Любое действие сразу пишется в IndexedDB и в `outbox`.
2. `POST /api/sync {ops: [...], since: <cursor>}` → сервер применяет изменения
   (побеждает запись с бо́льшим `updated_at`), возвращает всё с `rev > cursor` и новый курсор.
3. Триггеры: старт, событие `online`, возврат во вкладку, ~1 с после изменения, раз в 60 с.
4. Партнёр получает только «публичные» поля: процент дня, серии, достижения, отметку тренировки.
5. Service Worker: оболочка — stale-while-revalidate в `app-<hash>`, при смене хэша вкладки
   перезагружаются; `/api/*` — только сеть, при ошибке `{error: 'offline'}`; страница
   «Сервер недоступен» с ручным вводом адреса (как в vk-music).

## Локальная ИИ

Только по кнопке. `POST /api/ai/jobs` → `job_id`; клиент следит за статусом, результат
приходит обычной синхронизацией. Без связи запрос ставится в `outbox` и выполняется при
подключении. Задачи выполняются по одной; Ollama выгружает модель после простоя.

| Задача | Что делает код | Что делает ИИ |
|---|---|---|
| **Нормы** | Миффлин–Сан Жеор × активность, дефицит/профицит, белок 1,6–2,2 г/кг, вода 30 мл/кг, шаги | проверяет реалистичность целей и сроков, предлагает поправки, объясняет |
| **БЖУ еды** | ищет продукты в справочнике, считает суммы | разбирает текст в `[{продукт, граммы}]`, переводит штуки/ложки в граммы; для незнакомого продукта оценивает БЖУ на 100 г (помечается «≈ ИИ», сохраняется в справочник) |
| **Программа** | валидирует: только id из каталога, только доступное оборудование; раскладывает по дням календаря | собирает мезоцикл 4–6 недель: сплит, упражнения, подходы/повторы, прогрессия, разминка |
| **Разбор недели** | собирает статистику | пишет разбор тренера: что получилось, что нет, что поменять |

Техника выполнения упражнений всегда берётся из каталога, а не придумывается моделью.

## Мотивация

Два слоя: **мгновенный** — правила и шаблоны на клиенте (работает офлайн, без ИИ) и
**разбор от ИИ** — по запросу.

**Метрики (считаются кодом):** процент выполнения дня, серия дней ≥ 80 %, соблюдение
нормы калорий/белка, выполнение тренировок по плану, тренд веса против запланированного.

**Мгновенные реакции (шаблоны с подстановкой цифр, тон зависит от настройки пользователя):**
- закрыл день на 100 % → похвала; новая рекордная серия → отдельная;
- открыл приложение после пропуска → «2 дня без отметок. Серия сгорела» и т. п.;
- вечером день выполнен меньше чем наполовину → напоминание, что ещё можно успеть;
- пропущена плановая тренировка / перебор калорий / недобор белка → замечание;
- вес идёт по плану → похвала; стоит на месте 2+ недели → предложение пересчитать нормы.

**Серии и уровни:** серия дней, опыт за выполненные пункты, уровни.
«Заморозка» серии — одна на неделю, чтобы один пропуск не обнулял всё.

**Достижения:** первая неделя, 10 тренировок, 30 дней воды, −1/−3/−5 кг, 100 000 шагов за неделю и т. п.

**Пара:** видно, как день закрыл партнёр; совместная серия (оба ≥ 80 %); еженедельное сравнение.

## Экраны

- **Сегодня** — реплика тренера, чек-лист, вода кнопками +/−, шаги, быстрый ввод еды, кольцо выполнения.
- **Календарь** — месяц, дни раскрашены по проценту выполнения, точки тренировок; свой и партнёра.
- **День** — журнал и тренировка любой даты.
- **Тренировка** — упражнения с техникой, отметка подходов и фактического веса.
- **Питание** — приёмы пищи, итог против нормы, «Рассчитать БЖУ».
- **Прогресс** — вес, серии, достижения, разбор недели.
- **Профиль** — параметры, цели, инвентарь, тон, «Пересчитать нормы», «Составить программу».

Раскладка: на телефоне нижняя панель вкладок, на широком экране — колонка слева (как в transkribator).

## Ограничения

- PWA не читает шаги из «Здоровья» — шаги вводятся вручную.
- Push-уведомления на iOS требуют установленной PWA и доступа сервера к интернету (Apple Push).
